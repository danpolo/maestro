## What S1b built (don't redo — build on it)

**Selector.** `maestro/config.py` defines `RUNNERS`, `ConfigError` and `engineering_runner(document=None)`. The default is `legacy`. An unknown value, or an `engineering:` block that is not a mapping, raises.

**Branch point.** `orchestrator.main` reads the selector once, right after the halt/paused block.
- A `ConfigError` journals `runner_config_error` and returns 1.
- `_runner_switch_refusal(kind, state)` journals `runner_switch_refused` and returns 1. It refuses when:
  - the selector is `graph` and the legacy loop has `in_flight` or `awaiting-verification` work;
  - the selector is `legacy` and `task_runs` has `running` or `paused` rows.
- `graph` then creates `.orchestrator/control.sqlite3` if it is missing (journal `control_db_created`), and goes to `_graph_main(state)`. The legacy body is unchanged.

**`_graph_main` (orchestrator.py).**
- **Startup:** resumes `task_runs.status='running'` rows through `load_revision` and `WorkflowRunner(..., dispatcher=_facade.TmuxDispatcher(runner=subprocess.run))`.
- **Each poll:** runs the halt checks and `poll_control_commands([])`.
- **Opening runs:** each runnable task that is not complete, not parked, and has **no `task_runs` row** gets `compile_workflow(normalize_spec(task), workflow_id=f"wf_{task_id}", code_base_sha=head_sha(REPO, runner=subprocess.run))`, then `_wf_runner.start_run(...)`.
- **Driving runs:** calls `tick()`, `ingest_results()` and `settle()` on each live run.
  - An exception journals `graph_tick_failed`.
  - A run that is no longer `running` is dropped, with `graph_run_settled`.
- **Idle:** mirrors legacy (`queue_exhausted`, then `_idle_heartbeat_maybe`).
- Graph mode has **no** admission yet; that is W8.
- **Journal events:** `graph_run_opened`, `graph_run_resumed`, `graph_run_unresumable`, `graph_compile_refused`.

**Choke point.** `WorkflowRunner.dispatch` routes controller permissions to `execute_inline`; everything else goes to `WorkflowRunner.launch_worker(node, claim, *, at)`. `launch_worker` is the single agent-launch function, and its docstring says so. **W1's `resolve_agent`, W3's attempt record and later W4/W7 all attach inside or immediately around `launch_worker`. Never add a second launch path.** W1 also needs the claim deadline (`claim()`), so the binding may have to be resolved before `claim`. If so, keep one function that owns "resolve, then claim, then launch" and have `tick` call it. That keeps the choke point single.
