## 3. Live CLI facts (claude 2.1.283, probed 2026-09-28, haiku, outputs in `maestro-wt/probe/out*.json`)
- **What `dontAsk` does:**
  - An allowed command runs.
  - A command that is not allowed is denied with `Permission to use Bash has been denied because Claude Code is
    running in don't ask mode.` There is no classifier involved.
  - `--output-format json` lists these under `permission_denials`.
- **How rules match:**
  - `Bash(git status *)` also matches a bare `git status`.
  - Compound commands (`echo hi && touch x`) are checked part by part.
  - `timeout N` is stripped.
  - A leading wildcard works: `Bash(*/.venv/bin/python *)`.
- **Redirects and file writes:**
  - A redirect such as `echo x > path` is governed by the Write/Edit path rules.
  - `--add-dir` alone does NOT allow writing there.
  - The rule `Write(/<abs>/**)` (so `//home/...`) allows the workspace; a path outside it is denied. This is why every
    writable call gets rules for cwd plus `add_dirs` (the workspace).
- **Reads:** a bare `Read` allows reads anywhere. `--disallowedTools "Read(**/.env)"` denies `.env`. `Bash(cat *.env*)`
  and `Bash(* .env*)` denied `cat .env` and `grep TOKEN .env`.
- **Known limit, recorded in the module docstring:** an allowed interpreter can still read a secret, e.g.
  `python3 -c 'open(".env")'`. The list guards commands; it is not a sandbox.
- **Not yet probed:** `cd sub && ls` (is `cd` allowed without a rule?), and Glob/Grep under `dontAsk`. Check both in
  the final live probe.
