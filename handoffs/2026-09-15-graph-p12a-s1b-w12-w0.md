## W0 design (from S1a's reading — build this)

**Selector (`maestro/config.py`).**
- Add `RUNNERS = ("legacy", "graph")`, a `ConfigError(ValueError)`, and `engineering_runner(document=None) -> str`.
- An absent block or key returns `legacy`.
- A non-dict `engineering:` block, or an unknown value, raises `ConfigError` naming the value and the allowed set. That follows the `workflow_policy_path` precedent, not `thresholds`' leniency.
- `_load_project_yaml` collapsing a broken file to `{}` → `legacy` is acceptable.

**Branch point (`orchestrator.main`, L1783).**
- After the halt/paused block (L~1816) and before `_reconcile_and_persist_startup_state`, read the selector once per process.
- Refusals, both with a reason, `append_journal("runner_switch_refused", reason)`, print, `return 1`:
  - `graph` while legacy work is active: `state["in_flight"]` is non-empty, or `waiting_on_dan` holds `kind == "awaiting-verification"`.
  - `legacy` while the control store has `task_runs` with `status IN ('running','paused')`.
- `grep` confirmed that nothing in legacy/migration code writes `task_runs`. Only `runner.start_run` and `compiler.apply_repair` do, so the legacy-side check cannot fire on a legacy project.
- `graph` → `return _graph_main(state)`. The legacy body stays byte-for-byte unchanged.

**Control store — known hazard.**
- `maestro.state.control_store()` opens and caches the controller store **only if `CONTROL_DB` exists**, and **its existence flips state authority**: `read_state`/`write_state`/`append_journal` then go through SQLite events.
- Always get the store via `maestro.state.control_store()`. Never call a second `ControlStore.open_controller`, which conflicts with the cached controller lock.
- If it returns `None` in graph mode, the recommended default is to refuse with a reason naming the missing `.orchestrator/control.sqlite3`. Creating the DB silently migrates the project's state authority. That is a scope/risk decision, so **ask Dan** (AskUserQuestion) before choosing "create it".

**`_graph_main` poll (per spec W0).**
- **Startup:** resume every `task_runs` row with `status='running'` via `load_revision(store, workflow_id, workflow_revision)` (compiler.py L864) → `WorkflowRunner(store, rev, run_id=..., repo=REPO, dispatcher=TmuxDispatcher(runner=subprocess.run))`. Use the orchestrator module's `subprocess`, which the lane harness doubles with `_Subprocess`, so no real tmux runs in tests.
- **Each iteration:** run the same halt/paused/HALT_FILE checks as legacy.
- **Open runs:** for each `parse_runnable_tasks()` task that is not complete, not parked, and has **no `task_runs` row at all** (any status; a finished or failed run is W7/operator territory and must not reopen every poll):
  - `rev = compile_workflow(normalize_spec(task), workflow_id=<convention — check tests/workflows + status fixtures>, code_base_sha=head_sha(REPO))`
  - `runner = _wf_runner.start_run(store, rev, repo=REPO, dispatcher=...)`
  - Reference `start_run` / `WorkflowRunner` through the module (`from maestro.workflows import runner as _wf_runner`), so tests can spy on `maestro.workflows.runner.start_run` and `WorkflowRunner.tick`.
- **Drive:** for each live runner, `tick()`, then `ingest_results()`, then `settle()`, in the spec's literal order. `tick` already ingests and settles internally, and the repeat is idempotent. Drop runners whose run is no longer `running`.
- **Idle/exhausted:** mirror legacy (`queue_exhausted` journal, phase idle, `_notify_proposal_test_due()`, sleep, continue). Otherwise `time.sleep(POLL_INTERVAL)`.
- **Never** call `launch_implementer` / `launch_async_job`, and add no threshold rotation (§4).

**Dispatch choke point (`runner.py` L679).**
- Split `dispatch`: the controller-permission branch stays, and the worker path moves into one method (e.g. `launch_worker(node, claim, *, at)`) with a docstring naming it the single agent-launch choke point for W1/W3/W4/W7 and the future gate.
- Every existing caller goes through it; no behaviour change. `tests/workflows` must stay green.

**Tests (`tests/graph_engineering/test_dispatch_wiring.py`, on `run_lane` from `tests/graph_engineering/conftest.py`).**
- **Harness:** `run_lane` writes ROADMAP + state.json into the sandbox and runs the real `main()`. End after one poll with `on_poll=lambda run: run.halt()`. Write `project.yaml` into the sandbox root. `config.PROJECT_YAML` is rebased, and `lane_sandbox` rebuilds the tree per call, so write it inside `on_poll` or before `run.run()`. You may need a small scenario hook: `LaneScenario` has no `project_yaml` field yet, and adding one is fine. The control DB also needs creating in the sandbox for graph mode.
- **Cases:**
  - `config`: default / graph / unknown raises / non-dict raises.
  - Legacy one-task poll: spies on `start_run` + `WorkflowRunner.tick` record 0.
  - Graph one-task poll: one `task_runs` row `running`, `run.commands` holds one `tmux new-window` for the first node, `run.launched == []`, and the `launch_async_job` seam is not in the trace.
  - Refusals, both directions (assert the journal reason text).
  - Restart: a second `main()` resumes the same run id and opens no new run.
- **Existing lane test pinning seams:** `_SEAMS` asserts that each name exists on some module, so don't rename seams.
